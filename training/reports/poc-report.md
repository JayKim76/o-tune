# 로드맵 0단계 PoC 결과 보고서 — 채점기 + 합성 케이스 100건

- 작성일: 2026-10-22
- 설계 근거: `docs/rl-tuning-design.md` 10장 로드맵 0단계
- 완료 기준(설계): "임의 후보 10건을 자동 채점해 DBA 수동 채점과 일치" — 본 PoC에서는
  후보 3종 × 100건 = 300건을 자동 채점해 **판정 순서의 일관성**으로 1차 검증했다.
  DBA 수동 채점과의 대조는 실측 단계(아래 "남은 검증")에서 수행한다.

## 산출물

| 항목 | 내용 |
|---|---|
| 채점 코어 | `training/scorer/scorer.mjs` — 보상 함수(설계 5.1 그대로), SELECT 전용 가드, 힌트 상충·남용 탐지, 결과셋 해시 동등성 |
| 실행 러너 | `training/scorer/oracleRunner.mjs` — node-oracledb 실행, elapsed 3회 중앙값, DBMS_XPLAN(ALLSTATS LAST)에서 Buffers·Cost 파싱 |

| 케이스 | 템플릿 10종 × 변형 10개 = 100건 (`training/cases/data/`), 결정적 생성 |
| 테스트 | 단위 테스트 총 17건 통과 (기존 7 + 신규 10), 빌드·린트 통과 |

## 배치 평가 결과 (드라이런, 100건)

케이스마다 후보 3종을 채점했다.

| 후보 | 기대 | 결과 |
|---|---|---|
| gold (정답 튜닝 SQL + 정답 지표) | 높은 점수 | 평균 **0.8902**, 중앙값 0.9989, 최소 0.1508 |
| copy (원본 SQL 그대로) | 0 근처 | 평균 **0.05** (형식 보너스만) |
| broken (DML 문장) | -1 | 100건 전부 **-1** (실행 전 가드 차단) |

- 판정 순서 위반(gold > copy > broken): **0건**
- 패턴별 gold 평균: 풀스캔·카테시안 계열 1.000, NL 남용 0.986~0.999, 카디널리티 왜곡 0.949,
  그룹바이 스캔 0.921, 조인 순서 0.896, **하드파싱(IN 리스트) 0.151**
- 하드파싱 케이스의 gold가 낮은 것은 의도된 결과다. 액세스 경로 개선 없이 파싱 부하만 줄이는
  튜닝은 buffer gets 개선이 거의 없어(계수 0.97) 보상도 낮게 설계되어 있다.
- 드라이런 보상은 개선 비율 기반이라 같은 패턴 안에서는 값이 동일하다. 실제 분산은 실측에서 생긴다.

## 단위 테스트로 검증한 것

- 가드: SELECT/WITH 허용, 리터럴 속 키워드 허용, DELETE·다중 문장·SELECT INTO 차단
- 보상: 큰 개선 1.0, 무개선 0.05, 실행 오류 -1, 결과 불일치 -1, 타임아웃 -0.2, 형식 위반 -0.5,
  상충 힌트 -0.2, 힌트 초과·MATERIALIZE 남용 감점
- 동등성: 행 순서와 무관한 해시, 값 변경 탐지
- 계획 파싱: `Cost (%CPU)`의 괄호 숫자(예: `1240 (2)`)를 잘못 읽던 버그를 테스트에서 발견해 수정
  (첫 숫자만 취하도록 변경)
- 케이스: 100건·고유 ID·정답 지표 우위·결정적 재생성

## 남은 검증 (다음 단계 진입 조건)

1. **샌드박스 실측**: Oracle Free 샌드박스에 케이스 스키마+데이터를 적재하고
   `--mode oracle`로 gold 후보를 채점해, 드라이런 점수와 실측 점수의 방향성 일치를 확인한다.
   이 환경(개발 VM)에는 Oracle이 없어 아직 수행하지 못했다.
2. **DBA 수동 채점 대조**: 임의 후보 10건에 대해 DBA 수동 판정과 채점기 verdict를 대조한다 (설계 완료 기준).
3. 실측을 통과한 케이스부터 `review.verdict`를 `approved`로 올리고, 실측 지표로
   `original_metrics`/`gold_metrics`를 교체한다 (`metrics_basis: "measured"`).
